# Mint-Chat-manager

Бот ВКонтакте на C# с использованием Long Poll API.

## Запуск

Нужен .NET 10 SDK и токен сообщества с доступом к сообщениям. ID сообщества по умолчанию: `232664735`.

В настройках сообщества включите сообщения, разрешите сообществу получать сообщения в беседах, включите Long Poll API и отметьте события `message_new` и `message_event`. Игровые подтверждения используют callback-события.

Настройки и ключи находятся в `Configuration/.env`. Создайте файл из шаблона и заполните значения:

```sh
cp Configuration/.env.example Configuration/.env
# укажите токен сообщества и сильный пароль PostgreSQL в Configuration/.env
docker compose --env-file Configuration/.env up -d postgres
dotnet run
```

Файл `Configuration/.env` игнорируется Git. Переменные, уже заданные в окружении процесса, имеют приоритет над значениями из файла. При необходимости ID сообщества можно переопределить через `VK_GROUP_ID`. Ошибки Long Poll и отправки ответов выводятся в консоль.

Параметры подключения к PostgreSQL задаются переменными `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD` в `Configuration/.env`. Файлы схемы и миграций хранятся в `Database/`; фактические данные PostgreSQL остаются в Docker volume `postgres_data`. База доступна только с локального компьютера.

## Команды

Перенесённые команды игрового раздела:

- `/баланс` (`/balance`, `/б`, `/bal`) — показать денежный счёт.
- `/банк` — положить наличные в банк; `/снятьбанк` — снять деньги с банковского счёта. Обе команды принимают сумму или `все`.
- `/передать` (`/pay`, `/transfer`) — запросить перевод по ссылке/упоминанию, ID или ответом на сообщение; перевод выполняется только после подтверждения автором команды.
- `/ежедневный` (`/ежедневный_бонус`, `/бонус`) — показать бонус дня и забрать его кнопкой. Награда повторяется по семидневному циклу, забрать её можно раз в 24 часа.
- `/btc`, `/купитьbtc`, `/продатьbtc` — курс и операции с Bitcoin.
- `/addaccesslevel` — назначить уровень прав; `/removerole` — снять его; `/staff` — показать состав; `/getrole` — сведения о должности; `/pin` и `/unpin` — закрепить или открепить сообщение (для закрепления ответьте на сообщение).
- `/warn`, `/unwarn`, `/mute`, `/smute`, `/unmute`, `/kick`, `/skick`, `/ban`, `/sban`, `/unban`, `/sunban`, `/clear`, `/mclear`, `/sclear`, `/smclear`, `/purge`, `/zov` — модерационные действия. `/lists` открывает категории активных предупреждений, мутов и банов с кнопочной навигацией. `/olist` и `/offlinelist` показывают онлайн- и офлайн-участников беседы с постраничной навигацией; для этих списков требуются роль от 2 либо права администратора беседы. `/purge` требует уровень 3 и удаляет только команды модерации в последних 200 сообщениях. `/zov` требует уровень 2 и подтверждение кнопкой; вызов ограничен одним на беседу каждые три минуты. Для остальных команд модерации требуются соответствующая роль и беседа; время блокировки чата можно указать, например, `30м` или `2ч`, срок бана — в днях.

- `/rules`, `/info`, `/setrules`, `/setinfo`, `/settings` — чтение и настройка сведений беседы; для изменения данных и настроек нужны права владельца беседы (уровень 6 или выше) либо системного администратора.
- `/snick`, `/gnick`, `/rnick` и `/nlist` — установка, просмотр, удаление и постраничный список Nick_Name в текущей беседе; требуется роль от 1. Данные хранятся отдельно для каждой беседы в `chat_nicknames` (миграция `004_chat_nicknames.sql`).
- `/silence` (`/тишина`, `/мутчат`, `/silent`) — включает режим тишины: бот удаляет сообщения участников с уровнем ниже 1; выключить режим можно повторной командой или кнопкой. Требуется уровень 3 или системный администратор.
- `/top` (`/топ`, `/топы`, `/пивозавры`) — игровые рейтинги сообщений в этой беседе, денег, банка, пива, Bitcoin и репутации с кнопками категорий.

Также доступны `/ping`, `/id`, `/stats` (`/стата`, `/профиль`), `/help` и `/помощь`. Справка открывает категории по уровням доступа и показывает только перенесённые обработчики. Минимальные уровни модерационных команд: модератор — 1, старший модератор — 2, администратор — 3, главный администратор — 4; назначение роли требует уровня 2, закрепление — уровня 4. `/start` доступна владельцу VK-беседы или системному администратору. Команды с префиксом `s` являются тихими и не отправляют уведомление при успешном выполнении.

`/stats` показывает статистику пользователя в текущей беседе; счётчики хранятся отдельно по peer ID. Миграция `003_chat_message_statistics.sql` сохраняет старые общие дневные счётчики с peer ID `0`; исторически распределить их по беседам нельзя.

Остальные актуальные обработчики исходного `server.ts` ещё не перенесены. По массиву `ALL_CANONICAL_COMMANDS` в исходнике пока не представлены 22 из 59 корневых командных семейств; алиас уже реализованного семейства считается покрытием. Этот перечень не включает все дополнительные обработчики `server.ts`, поэтому он не является полным счётчиком всего переноса. Команда не считается перенесённой, пока у неё нет рабочего обработчика; алиасы не учитываются как самостоятельные команды.

В новой беседе владелец или системный администратор может включить бота командой `/start`.

Текст ответов добавленных игровых команд приведён к формулировкам текущего `server.ts`. Хранилище валюты и ежедневных бонусов использует PostgreSQL и транзакционные обновления; прежние профили автоматически получают нулевые значения новых полей.

Сообщения и callback-события обрабатываются четырьмя параллельными обработчиками через ограниченную очередь из 64 событий. Для каждой группы одновременно разрешён только один экземпляр бота. Каждая публичная команда размещается в отдельном файле в `commands/`; общие помощники находятся вне этой папки.

Для постоянного запуска одним Docker Compose используйте `docker compose --env-file Configuration/.env up -d --build`; сервис `bot` зависит от здоровой базы и перезапускается после сбоя или перезагрузки Docker daemon, пока сервис не остановлен вручную. Не запускайте одновременно Compose-сервис `bot` и `dotnet run`: для локальной разработки оставляйте только PostgreSQL поднятым через Compose.

Настройки очереди, пулов HTTP/PostgreSQL и кэш имён VK вынесены в `Optimization/`. Кэш ограничен 2 048 записями и хранит имя до 10 минут. Менеджер процессов/контейнеров восстанавливает приложение после сбоя, но не может отменить принудительный сон или остановку виртуальной машины хостинг-провайдером: для работы после лимита простоя нужен always-on тариф/VM и соответствующая настройка idle timeout на выбранной платформе.

Для переноса команд с изображениями доступны отправка загруженного PNG через `SendPhotoAsync` и отправка готового VK attachment ID вместе с текстом через `SendMessageWithAttachmentAsync`. Сами фото-команды и генераторы изображений из исходника ещё не считаются перенесёнными, пока не добавлены их обработчики и источники/кэш изображений.
